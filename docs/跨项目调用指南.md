# 跨项目调用 QuantBacktest

QuantBacktest 是数据、因子评价、事件回测和候选审核平台。新回测只使用 Python 脚本，**不需要也不接受 YAML**。

```text
原始因子 Python → 因子指标与候选审核
事件策略 Python → 策略指标与交易证据（手工关联到候选）
```

因子与策略是两条独立链路：因子运行不会替你创造交易策略；策略运行也不会伪造因子 IC。

## 外部项目的 MCP 顺序

外部项目中的 Codex 不需要猜测文件格式。连接 MCP 后必须按下面顺序调用：

1. `create_factor_script(...)` 或 `create_strategy_script(...)`：平台在外部项目写入正确的单文件骨架；不会覆盖已有文件。
2. 在生成的 Python 文件中写入自己的因子公式或策略规则。
3. `validate_factor_script(...)` 或 `validate_strategy_script(...)`：检查脚本、数据、字段、样本期、账户和交易能力；不会创建运行。
4. 仅当返回 `valid: true` 时，调用 `run_factor_tool(...)` 或 `run_backtest_tool(...)`。运行工具会再次校验实际文件。

即使跳过生成器直接写脚本，校验和运行仍会阻断不符合契约的文件，并返回错误、能力差异及可下载的数据清单。平台不会自动联网下载、猜测字段或改写成代理策略。

## 因子 Python 文件

一份文件只产生一个原始因子。`initialize` 明确声明本地数据和评价口径；`main` 在每个形成时点被调用一次，`context.history` 只能看到该时点及之前的数据。

```python
from quantbacktest.api import *
import pandas as pd


def initialize(context):
    context.set_name("cross_sectional_momentum")
    context.set_data(
        adapter="binance_zip",
        path="data/raw/binance/spot_klines",
        market="spot",
        frequency="1h",
        symbols=["BTCUSDT", "ETHUSDT", "SOLUSDT"],
        start="2024-01-01T00:00:00Z",
        end="2024-06-30T23:00:00Z",
    )
    context.set_factor_evaluation(
        formation="daily",       # "bar" / "daily" / "weekly"
        horizon_bars=24,
        entry_price="next_open", # "close" / "next_open"
        exit_price="close",      # "close" / "open"
        direction="higher_predicts_higher_return",
        groups=3,
        weighting="equal",       # "equal" / "factor_value"
        fee_bps=5.0,
        slippage_bps=2.0,
    )


def main(context):
    rows = []
    for symbol in context.symbols:
        bars = context.history(symbol, 25, fields=["close"])
        if len(bars) == 25:
            rows.append({
                "timestamp": context.now,
                "symbol": symbol,
                "factor": bars["close"].iloc[-1] / bars["close"].iloc[0] - 1,
            })
    return pd.DataFrame(rows, columns=["timestamp", "symbol", "factor"])
```

返回表必须有 `timestamp`（或 `date`）、`symbol`（或 `instrument`）、`factor` 三列；所有输出行的时间必须等于当前 `context.now`，同一时间—交易对不可重复。空表、全空、非数值和重复输出会失败，也不会建立候选。

多资产报告包含 IC、Rank IC、ICIR、覆盖率、单调性、分组前瞻收益、**Group Cumulative Returns**、Top–Bottom 多空组合、成本前后累计/年化收益、波动率、Sharpe、最大回撤和换手。单资产报告改为时序相关、分位收益、覆盖率和暴露，横截面 IC 明确标为“不适用”。Fama–MacBeth 当前不支持。

每次完整成功的因子运行自动在核心 `factor_library` 建立独立候选，封存 Python 快照、运行声明、数据清单、因子表、指标和 HTML 报告；候选仍须人工批准。

## 事件策略 Python 文件

策略脚本自己定义信号、选币、权重、止损、仓位上限与调仓。平台只做账户、撮合、成本和审计。

```python
from quantbacktest.api import *


def initialize(context):
    context.set_name("ma_trend_strategy")
    context.set_data(
        adapter="binance_zip",
        path="data/raw/binance/spot_klines",
        market="spot",
        frequency="1h",
        symbols=["BTCUSDT", "ETHUSDT"],
        start="2024-01-01T00:00:00Z",
        end="2024-06-30T23:00:00Z",
    )
    context.set_account(
        initial_cash=100_000.0,
        benchmark="BTCUSDT",  # 或 "equal_weight_universe"
        fee_bps=5.0,
        slippage_bps=2.0,
    )
    run_daily(rebalance, when="close")


def rebalance(context):
    weights = {}
    for symbol in context.symbols:
        bars = context.history(symbol, 20, fields=["close"])
        if len(bars) == 20 and bars["close"].iloc[-1] > bars["close"].mean():
            weights[symbol] = 0.5
    order_target_weights(weights)
```

支持 `run_daily`、`run_weekly`、`run_every_bars`、`history`、`get_bars`、`order_target_weights`、`order_value`、`order_target` 与账户/持仓/订单查询。开盘事件订单按该 K 线 `open` 成交，当前 K 线的 `high/low/close` 不可见；收盘事件订单按已完成 K 线 `close` 成交。

现货仅支持现金多头；余额不足会拒单并记录原因，绝不自动缩放、透支或做空。Bybit 线性合约需要逐仓、杠杆、资金费率和本地合约规格；任一项缺失时停止并返回下载清单。

策略报告独立展示策略净值、基准净值和回撤，另外提供 Sharpe、最大回撤、持仓、订单、成交、拒单、成本、实际数据范围及合约审计项。策略不会自动成为因子候选；在 Web“候选审核”中手工关联为指定因子候选的交易证据。

## CLI

在 `backtest-system` Python 3.11 专用环境中运行：

```powershell
cd E:\research\my_project
quantbacktest factor-validate factors\momentum.py
quantbacktest factor-run factors\momentum.py
quantbacktest strategy-validate strategies\trend.py
quantbacktest strategy-run strategies\trend.py
```

运行工件写入 `<项目根目录>/results/backtests/`。其中 `run_spec.json` 是平台内部生成的原生 Python 运行声明，不是用户需要维护的 YAML 配置。

## 本地数据范围与能力边界

第一阶段支持已有本地 `binance_zip` 现货 K 线、`bybit_parquet` 线性合约 K 线和 `crypto_top50` 数据，标准字段为 `timestamp`、`symbol`、`open`、`high`、`low`、`close`、`volume`、`turnover`。

请求 A 股、订单簿、链上数据、`dai`/`jqdata`、不存在字段、缺失资产/频率/样本期或 Fama–MacBeth 时，平台会停止并给出所需数据清单；不会静默替换为其它数据，也不会擅自创建论文代理策略。

历史 YAML 运行目录和既有候选仅保留只读审计价值，不能作为新的公开运行入口。
